Skill Fundamentals & Core Concepts

This section introduces the foundational concepts of Claude Skills. Here, you will learn what a skill is, the core design principles guiding their creation, and the crucial relationship between Skills and the Model Context Protocol (MCP). Understanding these fundamentals is essential before building your own workflows, as it establishes the "why" behind the technology.

✨ What is a Skill?

A skill is a set of instructions - packaged as a simple folder - that teaches Claude how to handle specific tasks or workflows. Instead of re-explaining your preferences and domain expertise in every conversation, skills let you teach Claude once and benefit every time.

  • ✓ Highly powerful for repeatable workflows.
  • ✓ Works well with code execution and document creation.
  • ✓ Adds a knowledge layer to MCP raw tool access.

📐 Core Design Principles

1. Progressive Disclosure

A three-level system to minimize token usage: Level 1 (YAML frontmatter) for discovery, Level 2 (SKILL.md body) for main instructions, Level 3 (Linked files) for deep context.

2. Composability

Claude can load multiple skills simultaneously. Skills should work well alongside others.

3. Portability

Works identically across Claude.ai, Claude Code, and the API.

The Kitchen Analogy: MCP vs. Skills

MCP provides the professional kitchen (tools, ingredients). Skills provide the recipes (step-by-step instructions).

Model Context Protocol (Connectivity)

  • 🔌 Connects Claude to your service (Notion, Asana).
  • 🔧 Provides real-time data access and tool invocation.
  • ❓ Defines WHAT Claude can do.

Claude Skills (Knowledge)

  • 📚 Teaches Claude how to use your service effectively.
  • 📋 Captures workflows and embedded best practices.
  • 💡 Defines HOW Claude should do it.

Skill Architecture & Creation

This section details the strict technical requirements for building a skill. You will interact with a visual representation of the required folder structure and utilize an interactive YAML builder tool. This hands-on approach ensures you understand the exact formatting rules (like kebab-case naming and progressive disclosure) required for Claude to successfully recognize and trigger your skill.

Folder Structure

A skill is packaged as a standard directory. The naming conventions are strict.

📁 your-skill-name/
📄 SKILL.md (Required)
Must be exactly SKILL.md. No variations.
📁 scripts/ (Optional)
📄 process_data.py
📁 references/ (Optional)
📄 api-guide.md
📁 assets/ (Optional)
Critical Rule: Do not include a README.md inside the skill folder. All documentation goes in SKILL.md or references/.

Interactive YAML Frontmatter Builder

The YAML frontmatter is how Claude decides whether to load your skill. It acts as the first level of progressive disclosure. Try building one below to see the formatting rules applied in real-time.

Must be kebab-case. No spaces or capitals.

Include specific trigger phrases. No XML tags (< >).

Preview: SKILL.md
---
name: your-skill-name
description: What it does. Use when user asks to [specific phrases].
---

Workflow Patterns & Use Cases

Explore the common structural patterns observed in highly effective skills. This section categorizes skills by their operational flow, helping you choose the right architectural approach for your specific problem. Reviewing these patterns will guide you whether you are orchestrating multiple MCP servers or building a localized iterative refinement loop.

1. Sequential Workflow

→

Use when users need multi-step processes in a specific order with hard dependencies.

Step 1: Create Account
Step 2: Setup Payment (waits for Step 1)
Step 3: Create Subscription

2. Multi-MCP Coordination

🔗

Use when workflows span multiple distinct services and require data passing.

Phase 1: Figma MCP (Export)
Phase 2: Drive MCP (Store)
Phase 3: Linear MCP (Create Tasks)

3. Iterative Refinement

↻

Use when output quality improves with iteration, validation scripts, and self-correction.

Draft → Validate Script → Identify Issues
Loop: Fix Issues → Re-validate
Finalize & Save

4. Context-Aware Selection

⍺

Use when the desired outcome is the same, but the tool chosen depends on specific context.

If Size > 10MB: Use Cloud Storage
If Code: Use GitHub MCP
Else: Use Local Storage

5. Domain Intelligence

🧙

Use when your skill adds highly specialized knowledge or compliance rules before taking action.

Fetch Details → Apply Compliance Rules
If Passed: Process Action
If Failed: Flag for Review & Audit

Testing Methodologies

  • 1. Triggering Tests

    Ensure the skill loads at the right times. Test obvious tasks, paraphrased requests, and ensure it ignores unrelated topics.

  • 2. Functional Tests

    Verify outputs are correct, API calls succeed, and error handling works perfectly for edge cases.

  • 3. Iteration Triggers

    If undertriggering: add detail to description. If overtriggering: add negative triggers ("Do NOT use for...").
